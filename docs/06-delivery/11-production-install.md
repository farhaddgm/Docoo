# راهنمای سادهٔ نصب Docoo روی سرور

این راهنما برای کسی نوشته شده که متخصص فنی نیست. همهٔ کارهای فنی (ساخت برنامه، پایگاه‌داده، گواهی HTTPS، رمزها، پشتیبان‌گیری) را یک اسکریپت انجام می‌دهد؛ شما فقط چند چیز را می‌خرید یا می‌سازید و چند سؤال را جواب می‌دهید. همین فرایند در هر Pull Request با گردش‌کار **Deploy smoke** روی یک ماشین تازه آزموده می‌شود.

## ۱. چیزهایی که لازم دارید

| مورد                                                | چرا                                   | پیشنهاد                                                                                          |
| --------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------ |
| یک سرور مجازی (VPS) با Ubuntu 24.04                 | Docoo روی آن اجرا می‌شود              | دست‌کم ۴ هستهٔ CPU، ۸ گیگابایت RAM، ۸۰ گیگابایت دیسک (همیشه ≥ ۱۰ گیگابایت خالی برای به‌روزرسانی) |
| یک دامنه                                            | نشانی سایت، مثلاً `docoo.example.com` | از هر ثبت‌کنندهٔ دامنه                                                                           |
| یک حساب GitHub با دسترسی به مخزن                    | گرفتن کد روی سرور                     | همین حساب فعلی شما                                                                               |
| (اختیاری ولی بسیار توصیه‌شده) یک فضای ذخیره‌سازی S3 | پشتیبان خارج از سرور                  | هر سرویس سازگار با S3                                                                            |
| (اختیاری) حساب ایمیل SMTP                           | ارسال ایمیل بازنشانی گذرواژه          | سرویس ایمیل سازمان یا یک سرویس ارسال ایمیل                                                       |
| کلید API هوش مصنوعی                                 | کار اصلی عامل‌ها                      | OpenAI یا Google Gemini یا Anthropic                                                             |

## ۲. تنظیم دامنه (DNS)

در پنل شرکتی که دامنه را از آن خریده‌اید دو رکورد از نوع **A** بسازید که هر دو به **IP سرور** اشاره کنند:

1. نام: `docoo` (یا هر نامی که می‌خواهید) ← IP سرور
2. نام: `files.docoo` ← همان IP سرور

این ۵ تا ۳۰ دقیقه طول می‌کشد تا فعال شود.

## ۳. ساخت کلید دسترسی GitHub برای سرور

چون مخزن خصوصی است، سرور برای گرفتن کد یک کلید فقط‌خواندنی لازم دارد:

1. در GitHub به **Settings → Developer settings → Personal access tokens → Fine-grained tokens** بروید و **Generate new token** را بزنید.
2. نام: `docoo-server`؛ مدت اعتبار: ۹۰ روز.
3. در **Repository access** گزینهٔ **Only select repositories** و مخزن `farhaddgm/Docoo` را انتخاب کنید.
4. در **Permissions → Repository permissions** فقط **Contents: Read-only** را بدهید.
5. **Generate token** را بزنید و رشتهٔ ساخته‌شده را موقتاً کپی کنید (فقط یک بار نشان داده می‌شود).

## ۴. اجرای نصب

1. با برنامهٔ ترمینال (در ویندوز: PowerShell) به سرور وصل شوید: `ssh root@IP-سرور`
2. این دو فرمان را یکی‌یکی بزنید (به‌جای `TOKEN` کلید مرحلهٔ ۳ را بگذارید):

```bash
git clone https://TOKEN@github.com/farhaddgm/Docoo.git /opt/docoo
sudo /opt/docoo/scripts/deploy/install.sh
```

3. اسکریپت چند سؤال می‌پرسد. اگر جوابی ندارید، Enter بزنید تا بعداً تنظیم شود:
   - دامنه (مثلاً `docoo.example.com`)
   - دامنهٔ فایل‌ها (پیش‌فرضش درست است؛ Enter)
   - ایمیل برای گواهی HTTPS و ایمیل مدیر
   - SMTP (اختیاری)، محل پشتیبان S3 (اختیاری ولی توصیه‌شده)، کلید تبدیل گفتار به متن (اختیاری)
4. ساخت بار اول ۱۰ تا ۲۰ دقیقه طول می‌کشد. در پایان یک **پیوند یک‌بارمصرف** چاپ می‌شود. آن را در مرورگر باز کنید و گذرواژهٔ خودتان (دست‌کم ۱۲ نویسه) را انتخاب کنید. اسکریپت هیچ گذرواژه‌ای از شما نمی‌پرسد و همهٔ رمزهای سیستم را خودش می‌سازد و در `/opt/docoo/deploy/.env*` نگه می‌دارد.

### اگر سرور از قبل سایت دیگری دارد

اگر روی سرور یک Caddy دیگر (در Docker) پورت‌های ۸۰ و ۴۴۳ را گرفته باشد، اسکریپت خودش آن را پیدا می‌کند و Docoo را **پشت همان Caddy** راه می‌اندازد. سایت‌های فعلی دست نمی‌خورند؛ فقط یک بلوک با نشانهٔ `# docoo:begin` به انتهای Caddyfile آن اضافه می‌شود (نسخهٔ قبلی با پسوند `.before-docoo` کنارش نگه داشته می‌شود) و گواهی HTTPS را همان Caddy می‌گیرد. برای جداکردن Docoo کافی است آن بلوک را پاک کنید. اگر کانتینر آن Caddy از نو ساخته شد، `install.sh update` اتصال را دوباره برقرار می‌کند. اگر پورت‌ها دست برنامهٔ دیگری باشد، اسکریپت پیش از هر تغییری متوقف می‌شود و پیام می‌دهد.

## ۵. وصل‌کردن هوش مصنوعی

1. وارد سایت شوید و از منوی کناری **ارائه‌دهندگان AI** را باز کنید.
2. ارائه‌دهنده را انتخاب کنید و کلید API را بچسبانید (راهنمای گرفتن کلید زیر همان فیلد نوشته شده است) و **ذخیره و بررسی اتصال** را بزنید. کلید رمز می‌شود و دیگر نمایش داده نمی‌شود.
3. در بخش **مدل پیش‌فرض پروژه‌ها** اتصال و مدل را انتخاب و ذخیره کنید.

## ۶. به‌روزرسانی به نسخهٔ جدید

سرور شما **دو راه** برای رسیدن به نسخهٔ تازه دارد و هر دو از آخرین نسخهٔ **منتشرشده** (تگ `vX.Y.Z`) نصب می‌کنند، نه آخرین کامیت `main`. هر تغییر وقتی به سرور می‌رسد که شمارهٔ نسخه در `package.json` بالا رفته و Release ساخته شده باشد (ساخت Release پس از مرج خودکار است).

### الف) خودکار، هر شب

نصب‌کننده یک تایمر systemd می‌گذارد که **هر شب حدود ساعت ۰۳:۳۰** (به وقت سرور، با چند دقیقه تأخیر تصادفی) نسخهٔ تازه را بررسی می‌کند:

- اگر نسخهٔ جدیدی نیامده باشد هیچ کاری نمی‌کند و چیزی را راه‌اندازی دوباره نمی‌کند.
- اگر نسخهٔ جدید آمده باشد آن را نصب می‌کند؛ تغییرات پایگاه‌داده خودکار اعمال می‌شود و داده‌ها حفظ می‌شوند.
- اگر نسخهٔ جدید سالم بالا نیامد، **خودش به نسخهٔ قبلی برمی‌گردد** و سایت سر پا می‌ماند (تغییرات پایگاه‌داده فقط افزایشی‌اند و کد قبلی روی آن‌ها کار می‌کند؛ [runbook](10-runbooks.md#rollback-release)). در این حالت ماجرا در لاگ ثبت می‌شود و باید علتش بررسی شود.
- اگر سرور آن ساعت خاموش بود، با روشن‌شدن بعدی جبران می‌کند.
- **پیش از ساخت** فضای خالی دیسک را می‌سنجد (حدود ۱۰ گیگابایت لازم است). اگر کم باشد imageهای نسخه‌های قدیمی و cache ساخت را پاک می‌کند؛ اگر باز هم کافی نبود **هیچ چیز را تغییر نمی‌دهد**، سایت با نسخهٔ فعلی کار می‌کند و در لاگ می‌نویسد که فضا کم است (شب بعد دوباره تلاش می‌کند). پس از هر به‌روزرسانی موفق هم imageهای قدیمی‌تر از دو نسخهٔ آخر پاک می‌شوند تا دیسک پر نشود.

سروری که پیش از این قابلیت نصب شده، با **یک بار** زدن دستور دستی زیر این تایمر را هم می‌گیرد.

```bash
sudo /opt/docoo/scripts/deploy/install.sh auto-update status   # وضعیت و زمان اجرای بعدی
sudo /opt/docoo/scripts/deploy/install.sh auto-update off      # خاموش‌کردن
sudo /opt/docoo/scripts/deploy/install.sh auto-update on       # روشن‌کردن
sudo journalctl -u docoo-update -n 80                          # گزارش آخرین بررسی‌ها
```

### ب) دستی، همین حالا

```bash
sudo /opt/docoo/scripts/deploy/install.sh update
```

این دستور همیشه اجرا می‌شود، چه به‌روزرسانی خودکار روشن باشد چه خاموش، و اگر همان لحظه بررسی شبانه در حال کار باشد منتظر پایانش می‌ماند. وقتی نسخهٔ تازه را همین حالا می‌خواهید یا به‌روزرسانی خودکار را خاموش کرده‌اید از این راه استفاده کنید.

## ۷. پشتیبان‌گیری

اگر محل S3 را داده باشید، پایگاه‌داده **به‌طور پیوسته** (هر ۵ دقیقه) و یک نسخهٔ کامل هر ۲۴ ساعت، و فایل‌ها هر ۲۴ ساعت به آنجا فرستاده می‌شوند (۷ نسخهٔ کامل نگه داشته می‌شود). بازگردانی تا هر ثانیه از این بازه ممکن است؛ مراحلش در [runbook](10-runbooks.md#backup-restore) است. اگر S3 را بعداً تهیه کردید، مقادیر `BACKUP_S3_*` را در `/opt/docoo/deploy/.env` پر کنید و `install.sh update` را بزنید.

## ۸. گزارش پذیرش سرور

برای اینکه ببینید همه‌چیز سر جایش است (و برای امضای private beta)، روی سرور بزنید:

```bash
cd /opt/docoo
sudo ./scripts/deploy/acceptance.sh > acceptance-$(date +%F).md
```

فقط می‌خواند و چیزی را تغییر نمی‌دهد. جدولی از کانتینرها، API، HTTPS و روزهای باقی‌ماندهٔ گواهی، دیسک، نسخه، به‌روزرسانی شبانه، پشتیبان خارج از سرور، ادمین، اتصال AI و ایمیل می‌دهد. `ACTION` یعنی کاری که فقط شما می‌توانید بکنید (مثلاً هنوز کلید AI وارد نشده) و `FAIL` یعنی خراب است. توضیح کامل و محل چسباندن گزارش: [پذیرش private beta](12-private-beta-acceptance.md).

## ۹. اگر چیزی کار نکرد

- وضعیت سرویس‌ها: `sudo docker compose --project-directory /opt/docoo/deploy -f /opt/docoo/deploy/compose.production.yaml ps`
- گزارش خطا: همان فرمان با `logs --tail 100` به‌جای `ps`
- اگر به‌روزرسانی با `No space left on device` یا «فضای خالی دیسک کافی نیست» ایستاد، دیسک سرور پر است. فضا را بسنجید و imageها و cache قدیمی را پاک کنید، بعد دوباره `install.sh update` بزنید (پایگاه‌داده در volume است؛ **`--volumes` نزنید**):

  ```bash
  df -h /
  sudo docker system df
  sudo docker builder prune -f
  sudo docker image prune -f
  df -h /
  ```

  اگر هنوز کمتر از ۱۰ گیگابایت خالی بود، `sudo docker image prune -a -f` را هم بزنید (imageهایی را که هیچ کانتینری استفاده نمی‌کند پاک می‌کند) یا دیسک را بزرگ‌تر کنید.

- اگر گواهی HTTPS ساخته نشد، معمولاً رکوردهای DNS هنوز فعال نشده‌اند؛ چند دقیقه بعد `install.sh update` را دوباره بزنید.

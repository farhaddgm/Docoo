# ADR-0046 — گفتگوی صوتی

وضعیت: **پذیرفته‌شده** (مالک در ۲۰۲۶-۱۱-۰۱ تأیید کرد؛ پیاده‌سازی گام‌به‌گام). [ADR-0042](0042-account-policies.md) و [ارکستراسیون ارائه‌دهندگان](../03-ai/04-provider-orchestration.md) را کامل می‌کند.

## زمینه

همهٔ گفتگوهای Docoo (اسمارت، گفتگوی مرحله، پرسش‌های تحلیل) متنی‌اند. مالک می‌خواهد ادمین بتواند با صدا حرف بزند و/یا پاسخ را بشنود، با دو سرویس‌دهندهٔ صوتی (OpenAI و ElevenLabs)، گزارش مصرف شفاف و جدا، و کنترل روی ذخیرهٔ صدا.

## تصمیم

### ۱. سه حالت گفتگو

هر گفتگو دو محور مستقل دارد: **ورودی** (`text | voice`) و **خروجی** (`text | voice`).

| ورودی ادمین | پاسخ Docoo | استفاده                 |
| ----------- | ---------- | ----------------------- |
| صدا         | متن        | دیکته؛ فقط STT          |
| صدا         | صدا        | مکالمهٔ کامل؛ STT + TTS |
| متن         | صدا        | شنیدن پاسخ؛ فقط TTS     |
| متن         | متن        | حالت فعلی (پیش‌فرض)     |

ترجیح پیش‌فرض هر ادمین در «حساب من» ذخیره می‌شود و هر جعبهٔ گفتگو یک انتخابگر کوچک دارد که فقط برای همان گفتگو عوض می‌شود. ورودی صوتی به‌معنای حذف کادر متن نیست؛ متن پیاده‌شده همیشه قابل ویرایش است.

### ۲. معماری: صدا یک لایه است، نه گفتگوی جدید

Docoo مدل گفتگوی صوتی بی‌واسطهٔ (speech-to-speech) نمی‌گیرد. خط لوله همیشه همان گفتگوی متنی موجود است:

```
ضبط → POST /voice/transcribe → متن (قابل ویرایش) → ارسال پیام متنی موجود → پاسخ متنی → POST /voice/speak → صدا
```

دلایل: (الف) همهٔ منطق گفتگو، دسترسی، سقف‌های ADR-0042، ممیزی و context-builder دست‌نخورده می‌ماند؛ (ب) ترانسکریپت همیشه ذخیره و جست‌وپذیر است؛ (ج) هر سه درخواست جدا و زیر سقف ۳۰ ثانیهٔ پروکسی وب‌اند (`MODEL_TIMEOUT_MS=25s` در `smart-chat.service.ts`)؛ (د) سرویس‌دهندهٔ صوتی و مدل متنی مستقل از هم تعویض می‌شوند. هزینهٔ این انتخاب تأخیر بیشتر از مدل بی‌واسطه است؛ پخش جمله‌به‌جمله (streaming) گام بعدی است، نه v1.

### ۳. سرویس‌دهنده‌ها

پورت جدید `SpeechProvider` در `@docoo/providers`، کنار آداپترهای مدل:

```ts
interface SpeechProvider {
  listVoices(): Promise<VoiceDescriptor[]>; // id، نام، زبان‌ها، جنسیت/سبک، نمونهٔ پیش‌شنیدن
  listModels(): Promise<SpeechModelDescriptor[]>; // kind: 'stt' | 'tts'
  transcribe(req: TranscribeRequest): Promise<TranscribeResult>; // متن، زبان، مدت، usage
  synthesize(req: SynthesizeRequest): Promise<SynthesizeResult>; // بایت‌های صدا، mime، usage
}
```

- **OpenAI** (`openai`): STT با خانوادهٔ `*-transcribe`/`whisper` و TTS با خانوادهٔ `*-tts`؛ فهرست صداها از کاتالوگ آداپتر. از همان اتصال ارائه‌دهندهٔ OpenAI موجود (کلید رمزشده، write-only) استفاده می‌کند؛ کلید دوم لازم نیست.
- **ElevenLabs** (`elevenlabs`): اتصال تازه در «ارائه‌دهنده‌ها» با همان ذخیرهٔ رمزشدهٔ `provider_secrets`؛ فهرست صداها و مدل‌ها از API زنده خوانده می‌شود (شامل صداهای کتابخانهٔ حساب).
- شناسهٔ مدل **هیچ‌جا در کد سخت‌کد نمی‌شود**؛ از کاتالوگ زندهٔ آداپتر خوانده می‌شود و ادمین انتخاب می‌کند (همان اصل بخش ۶ سند ارکستراسیون). آداپتر `fake` برای آزمون‌ها.
- افزودن سرویس‌دهندهٔ سوم فقط یک آداپتر است.

### ۴. تنظیمات سامانه (فقط مالک/ادمین سامانه، با نسخه‌بندی تنظیمات ADR-0004)

| کلید                         | معنا                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `voice.enabled`              | خاموش/روشن کل قابلیت (پیش‌فرض خاموش)                                                  |
| `voice.provider`             | `openai` یا `elevenlabs` (برند)                                                       |
| `voice.stt_model`            | شناسهٔ مدل تبدیل گفتار به متن (نسخهٔ AI) از کاتالوگ همان برند                         |
| `voice.tts_model`            | شناسهٔ مدل تبدیل متن به گفتار (نسخهٔ AI) از کاتالوگ همان برند                         |
| `voice.voice_id`             | صدای پاسخ از فهرست صداهای همان سرویس‌دهنده، با دکمهٔ «پیش‌شنیدن»                      |
| `voice.speed`                | سرعت پخش (۰٫۷–۱٫۲۵)                                                                   |
| `voice.language_hint`        | پیش‌فرض: زبان رابط (`fa`/`en`)، برای بهبود دقت STT                                    |
| `voice.max_record_s`         | سقف مدت ضبط (پیش‌فرض ۱۲۰ ثانیه)                                                       |
| `voice.max_tts_chars`        | سقف نویسه برای هر پخش؛ پاسخ طولانی‌تر خلاصه‌وار خوانده نمی‌شود، بریده با اعلام می‌شود |
| `voice.store_admin_audio`    | ذخیرهٔ صدای ادمین در هر گفتگو (پیش‌فرض **خاموش**)                                     |
| `voice.audio_retention_days` | مدت نگهداری صدای ذخیره‌شده (پیش‌فرض ۳۰؛ ۰ = تا حذف دستی)                              |

اعتبارسنجی هنگام ذخیره: مدل و صدای انتخابی باید در کاتالوگ زندهٔ همان برند وجود داشته باشند؛ در تغییر برند، مدل و صدا ریست می‌شوند. دکمهٔ «آزمون اتصال صوتی» یک جملهٔ کوتاه می‌سازد و پخش می‌کند.

### ۵. گزارش مصرف جدا و شفاف

جدول جدید `voice_invocations` (مهاجرت جدید)، **جدا از** `model_invocations` تا هزینهٔ صدا در هزینهٔ مدل متنی گم نشود:

`id, provider, connection_id, kind (stt|tts), model, voice_id, actor_id, conversation_id, message_id, audio_seconds (STT)، characters (TTS)، input_tokens/output_tokens (اگر سرویس‌دهنده گزارش کند)، cost_usd، price_id، latency_ms، status، error_code، created_at`.

- قیمت‌ها از کاتالوگ قیمت موجود (`price-catalog`) با واحدهای تازه: به‌ازای دقیقه، هزار نویسه یا توکن؛ مصرفی که قیمت ندارد «بدون قیمت» نشان داده می‌شود، نه صفر.
- صفحهٔ **هزینه‌ها** (`/costs`) تب «صدا» می‌گیرد: جمع و روند به تفکیک سرویس‌دهنده، مدل، STT/TTS، کاربر و روز؛ ثانیه‌ها و نویسه‌ها کنار هزینه؛ خروجی قابل دریافت. جمع کل سامانه هر دو (متن + صدا) را جدا و در کنار هم نشان می‌دهد.
- سقف‌های ADR-0042 اعمال می‌شوند: مسیرهای صدا `@UsesAi()` می‌گیرند و بررسی «روشن بودن AI برای حساب» و سقف روزانه/ماهانه را رد نمی‌کنند. تصمیم‌ها در بخش «پرسش‌های باز».

### ۶. ذخیرهٔ صدا و حذف

- **ترانسکریپت همیشه** به‌عنوان متن پیام ذخیره می‌شود (مثل امروز). **خود صدا** فقط وقتی `voice.store_admin_audio` روشن باشد.
- صدای ذخیره‌شده در `object-store` موجود (کلید رمزنگاری‌شده) و ردیف فراداده در جدول `conversation_audio` (`message_id, owner_id, object_key, mime, bytes, duration_ms, expires_at`) می‌ماند، با RLS هم‌سطح پیام‌ها: هر ادمین فقط صدای خودش را می‌شنود؛ مالک فقط فراداده و «حذف» را می‌بیند، نه محتوا.
- پخش مجدد: دکمهٔ ▶ کنار پیام ادمین (فقط اگر ذخیره شده باشد).
- **حذف:** (الف) حذف صدای یک پیام، (ب) «پاک کردن صداهای این گفتگو»، (پ) «پاک کردن همهٔ صداهای قبلی من» در تنظیمات، (ت) مالک: «پاک کردن همهٔ صداهای سامانه». حذف، شیء را در object-store واقعاً پاک می‌کند، متن پیام را نگه می‌دارد و در ممیزی (`voice.audio.deleted` با شمار، بدون محتوا) ثبت می‌شود. `RetentionService` موجود صداهای گذشته از `expires_at` را خودکار پاک می‌کند.
- **صدای Docoo (TTS) ذخیره نمی‌شود.** مرورگر در طول نشست آن را نگه می‌دارد؛ پخش دوباره پس از رفرش یک فراخوانی TTS تازه (و هزینهٔ تازه) است و در UI گفته می‌شود.
- هنگام ذخیره‌نکردن، بایت‌های ضبط فقط در حافظهٔ درخواست می‌مانند و روی دیسک نوشته نمی‌شوند. در لاگ و ردیابی هرگز محتوای صدا یا کلید ثبت نمی‌شود.

### ۷. رابط

- کامپوننت مشترک `VoiceControls` + هوک `useVoiceChat` در `apps/web`، قابل‌استفاده در هر جعبهٔ گفتگو (چت اسمارت `chat-tab.tsx`، گفتگوی مرحلهٔ `stage-chat.tsx`، و هر گفتگوی بعدی).
- **دکمهٔ ضبط** (میکروفون): کلیک برای شروع/پایان، نمایش موج و زمان، لغو؛ پس از پایان متن پیاده‌شده در کادر می‌آید (یا اگر ادمین «ارسال خودکار» را روشن کرده، مستقیم فرستاده می‌شود). مجوز میکروفون و HTTPS لازم است؛ در نبود آن‌ها پیام راهنمای فارسی/انگلیسی.
- **دکمهٔ صدای اسپیکر:** بلندی (لغزنده)، قطع/وصل، و ▶/⏸ کنار هر پاسخ. در حالت خروجی صوتی، پاسخ جدید خودکار پخش می‌شود و ادمین می‌تواند هر لحظه قطعش کند. پخش یک‌سری است (دو پاسخ هم‌زمان نمی‌خوانند).
- انتخابگر حالت (چهار چیپ) در سربرگ جعبه؛ اگر قابلیت خاموش یا سرویس‌دهنده پیکربندی‌نشده باشد، دکمه‌ها به‌جای پنهان‌شدن، غیرفعال با علت (مثلاً «صدا در تنظیمات سامانه فعال نیست») نشان داده می‌شوند.
- دسترس‌پذیری: همهٔ دکمه‌ها با صفحه‌کلید، برچسب `aria`، اعلام وضعیت ضبط/پخش؛ متن پیاده‌شده جایگزین متنی صدا است. RTL/LTR و دو زبان فارسی/انگلیسی مثل بقیهٔ رابط.

### ۸. API

همه زیر `/voice`، پشت guard فعلی (نشست، CSRF، سیاست حساب):

- `GET /voice/config` — وضعیت برای رابط (روشن؟ برند، مدل‌ها، صدا؛ بدون راز).
- `GET /voice/catalog?provider=` — مدل‌ها و صداهای زندهٔ سرویس‌دهنده (تنظیمات).
- `POST /voice/preview` — پیش‌شنیدن یک صدا.
- `POST /voice/transcribe` — چندبخشی (`audio`، `conversationId?`، `locale`)؛ حداکثر ۱۰ مگابایت و `voice.max_record_s`؛ mime مجاز `audio/webm|ogg|mp4|wav|mpeg`، با بررسی امضای فایل. خروجی: `{ text, language, durationMs, audioId? }`.
- `POST /voice/speak` — `{ messageId }` یا `{ text }` (فقط متن پیام‌های خود کاربر/دستیار گفتگوهای خودش)؛ خروجی: جریان صوتی.
- `GET|DELETE /voice/audio/{id}`، `DELETE /voice/audio?conversationId=`، `DELETE /voice/audio` (همهٔ مال من)، `DELETE /owner/voice/audio` (مالک).
- `GET /voice/usage` و `GET /owner/voice/usage` — داده‌ی تب «صدا».

خطاها با `problem+json` موجود: `VOICE_DISABLED`، `VOICE_NOT_CONFIGURED`، `VOICE_AUDIO_TOO_LARGE`، `VOICE_AUDIO_INVALID`، `VOICE_PROVIDER_ERROR`.

### ۹. امنیت و حریم خصوصی

- کلیدها فقط سمت سرور؛ مرورگر هیچ‌گاه با OpenAI/ElevenLabs مستقیم حرف نمی‌زند.
- صدا داده‌ی شخصی است: به سرویس‌دهندهٔ بیرونی می‌رود، پس در «ارائه‌دهنده‌ها» و صفحهٔ تنظیمات صدا هشدار روشن نوشته می‌شود؛ `store`/retention سرویس‌دهنده، جایی که API اجازه می‌دهد، خاموش درخواست می‌شود و سیاست آن در سند ارائه‌دهنده ثبت می‌شود.
- ورودی صوتی پس از تبدیل به متن، **همان ورودی غیرقابل‌اعتماد متن** است (همان دفاع prompt-injection).
- محدودیت نرخ برای هر کاربر روی `transcribe` و `speak`؛ درخواست رهاشده لغو می‌شود تا هزینه نسوزد.
- رویدادهای ممیزی: تغییر تنظیمات صدا، حذف صدا، آزمون اتصال.

## گام‌های پیشنهادی توسعه (هرکدام یک PR)

1. **قرارداد و داده (انجام شد):** انواع در `@docoo/contracts`، پورت `SpeechProvider`، مهاجرت‌های `voice_invocations` و `conversation_audio`، تنظیمات `voice.*`، آداپتر `fake`.
2. **آداپتر OpenAI و ElevenLabs (انجام شد)** + کاتالوگ مدل/صدا + اتصال ElevenLabs. قیمت‌گذاری مصرف با حسابداری در گام ۳ می‌آید؛ آزمون پذیرش با کلید واقعی و سنجش کیفیت فارسی هنوز مانده است.
3. **API (انجام شد):** `/voice/*`، حسابداری مصرف، سقف‌های ADR-0042، ممیزی، ذخیره/حذف صدا. پاک‌سازی صداهای منقضی با `POST /voice/workspace-audio/purge-expired` (مالک) انجام می‌شود؛ زمان‌بندی خودکار آن به اجرای نگهداشت (retention) موجود وصل می‌شود، نه یک کار پس‌زمینهٔ تازه.
4. **تنظیمات و ارائه‌دهنده‌ها (وب):** صفحهٔ «صدا» در تنظیمات سامانه، انتخاب برند/مدل/صدا با پیش‌شنیدن، اتصال ElevenLabs، آزمون اتصال، حذف صداها.
5. **جعبه‌های گفتگو (وب):** `VoiceControls` در چت اسمارت و گفتگوی مرحله، سه حالت، ضبط، اسپیکر.
6. **گزارش هزینه:** تب «صدا» در `/costs`، خروجی، و پایان مستندات/CHANGELOG/آزمون E2E.

## گزینه‌های ردشده

- **مدل بی‌واسطهٔ گفتار‌به‌گفتار (Realtime API):** تأخیر کمتر، اما منطق گفتگو، دسترسی و سقف‌ها را دور می‌زند و به یک سرویس‌دهنده می‌بندد؛ بعداً به‌عنوان حالت اختیاری قابل بررسی است.
- **صدای مرورگر (Web Speech API) به‌جای سرویس‌دهنده:** رایگان اما کیفیت فارسی ناهمگون و بدون گزارش مصرف/کنترل.
- **ذخیرهٔ همیشگی صدای Docoo:** هزینهٔ ذخیره و بدون نیاز؛ بازتولید ارزان‌تر و ساده‌تر است.
- **ثبت مصرف صدا در `model_invocations`:** واحدهای متفاوت (ثانیه/نویسه) و خواستهٔ «گزارش مجزا» را می‌شکند.

## تصمیم‌های مالک

1. مصرف صدا مشمول سقف‌های فعلی حساب (ADR-0042) است؛ سقف جدا در نسخهٔ اول نیست.
2. متن پیاده‌شده پیش از ارسال در کادر پیام می‌آید و قابل ویرایش است؛ گزینهٔ «ارسال خودکار» در «حساب من» (پیش‌فرض خاموش).
3. برچسب «آزمایشی» برای کیفیت فارسی نمایش داده **نمی‌شود**؛ کیفیت فارسی هنوز در پذیرش گام ۲ سنجیده می‌شود.
4. تنظیمات سامانهٔ صدا فقط برای مالک است.

## پیامدها

- هر پاسخ صوتی یک فراخوانی پولی اضافه است؛ به همین دلیل پیش‌فرض قابلیت خاموش و حالت پیش‌فرض متن/متن است.
- ذخیرهٔ صدا داده‌ی حساس جدید ایجاد می‌کند؛ پیش‌فرض خاموش و دارای انقضا و حذف کامل است.
- تأخیر سه‌مرحله‌ای در v1 پذیرفته شده و با پخش جمله‌به‌جمله در آینده کم می‌شود.

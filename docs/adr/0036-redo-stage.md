# ADR-0036 — انجام دوباره یک مرحله

وضعیت: **پذیرفته‌شده**. به مدل run در [ADR-0010](0010-orchestration.md) و کارکرد workflow تکیه می‌کند؛ موتور Temporal تغییر نمی‌کند.

## زمینه

مدیر گاهی می‌خواهد مرحله‌ای را که تمام شده از اول انجام دهد (مثلاً منابع تحقیق کهنه بوده‌اند). تا امروز تنها راه، ساخت پروژهٔ تازه بود. هر `stage_run` در هر run یکتاست و workflow مرحلهٔ کامل را رد می‌کند؛ پس بازکردن دوبارهٔ همان ردیف، تاریخچهٔ خروجی‌ها، بازبینی‌ها و تأییدها را خراب می‌کرد.

## تصمیم

**انجام دوباره = run تازه با حمل مرحله‌های قبلی.** `POST /projects/{id}/workflow/redo` با `{stage, reason}`:

1. پروژه باید فعال باشد، اجرای زنده نداشته باشد (`WORKFLOW_RUN_LIVE`) و مرحله در آخرین run کامل شده باشد (`WORKFLOW_STAGE_NOT_COMPLETED`).
2. run تازه‌ای با `redo_from_stage` ساخته می‌شود و ردیف‌های `stage_runs` مرحله‌های کامل‌شدهٔ قبل از مرحلهٔ انتخابی در آن کپی می‌شوند (`status=completed`، همان `latest_output_id`، و `carried_from_stage_run_id` به ردیف مبدأ).
3. workflow مرحله‌های کامل را رد می‌کند و از مرحلهٔ انتخابی (و بعد از آن) از اول اجرا می‌کند. شمارندهٔ تلاش، گیت و خروجی‌ها تازه‌اند.
4. run قبلی، خروجی‌ها و بازبینی‌هایش دست‌نخورده می‌مانند. خواندن تاریخچهٔ مرحلهٔ حمل‌شده از ردیف مبدأ انجام می‌شود.
5. ثبت audit با رویداد `workflow.stage_redo_requested` و دلیل. مجوز همان `project.run` است.

## گزینه‌های ردشده

- بازکردن دوبارهٔ همان `stage_run`: تاریخچه و تأییدهای معتبر را از بین می‌برد و با یکتایی (run، مرحله) و بازپخش workflow ناسازگار است.
- تغییر workflow Temporal برای «بازگشت به مرحله»: خطر تغییر غیرقطعی (determinism) برای runهای در حال اجرا.

## پیامدها

- مهاجرت `0056`: ستون‌های `workflow_runs.redo_from_stage` و `stage_runs.carried_from_stage_run_id` (هر دو اختیاری؛ بازگشت امن).
- مصرف‌کنندگان خروجی مرحله‌های قبلی از `latest_output_id` می‌خوانند و بدون تغییر کار می‌کنند.
- رابط: دکمهٔ «انجام دوباره» کنار هر مرحلهٔ کامل در تب گردش‌کار (فقط بدون اجرای زنده)، با فرم دلیل و نشان «از اجرای قبل» برای مرحله‌های حمل‌شده.
